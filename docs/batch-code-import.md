# Android 批量 C 编码导入

入口：「库存 → 导入与扫码 → 批量 C 编码 / XLSX 导入」。原来的批量扫码页面也有同名按钮。

## 文本

选择目标库位，然后每行填写 C 编码与数量，用空格、制表符、英文或中文逗号分隔，例如：

```text
C25804 100
C14663 50
```

点击「加入并解析」，沿用现有批量入库流程：已有元件沿用本地资料，新元件通过原有资料查询补充，
缺少资料的行进入「待补充」。核对后点击确认入库，读取文件和解析本身不会修改库存。

## XLSX

点击「从 XLSX 导入」，读取第一个可见工作表的前三列：

| 第 1 列 | 第 2 列 | 第 3 列 |
| --- | --- | --- |
| C 编码 | 数量 | 已有库位编码 |
| C25804 | 100 | LOC-实际编码 |
| C14663 | 50 | 留空时使用界面选定库位 |

支持有表头或无表头、空行、共享字符串和数值单元格。表头可用「C编码 / 数量 / 库位编码」或「SKU / Quantity / Location」。
库位编码使用软件保存的库位 ID，不会按名称自动创建库位。需要新库位时先通过原有库位选择器创建。
沿用现有 XLSX 读取器，公式单元格需先粘贴为值；文件上限 10 MiB，每次最多 500 行，草稿总量仍最多 500 项。

数量必须是 1–2147483647 的整数。格式或库位错误会提示原始行号，并拒绝本次输入，避免部分导入。
同一次输入中相同 C 编码、相同库位的数量合并，不同库位分别保留；合计数量溢出也会拒绝。
重新导入时按「C 编码 + 库位」检查与当前草稿的重叠，列出每个重叠项的原数量和本次数量，
在用户选择前不修改草稿或库存。相同内容重导也需要明确选择：

- **替换重叠草稿行**：本次数量取代该编码/库位已有的未入库草稿行，其他行保留，新项目正常加入。
- **作为新增数量追加**：保留原草稿，再加入本次全部数量；这是额外入库，复核后才写入库存。
- **取消**：保留原草稿，返回输入界面。

例如先导入 `C123 2`、`C456 3`，把第二行改为 `C456 4` 后重导：替换得到 `C123 2`、`C456 4`；
只有明确选择追加才会得到合计 `C123 4`、`C456 7`。文本和 XLSX 采用同一重叠确认流程。
若重叠记录已入库（含已有入库回执的记录），不能替换；需要更正原库存时使用库存调整，
仅在确实需要额外入库时选择追加。原入库回执与已入库行保持不变。

## 实现边界

新增代码只负责读取两列文本/三列 XLSX、校验、重叠确认与生成 `BatchJlcRow`，接入已有的
`processRows`、`InventoryRepository.enrichImportCandidate`、`commitBatchJlc` 和回执防重机制。
未修改原有元件识别规则、资料查询实现、数据库结构、扫码流程或立创 XLS 对账单解析器。
