# 嘉立创连续采集与批量入库

Android 从“库存 → 导入与扫码 → 批量嘉立创入库”进入。采集包装二维码后结束扫码，再统一解析、核对数量和库位并确认入库。立创商城对账单使用同一入口中的[订单文件导入](storage-and-backup.md#立创订单对账单导入)。

## 扫码间隔与成功反馈

Android 在批量采集页的“扫码设置”中提供连续采集间隔，默认 1.5 秒，
可在 0.5–5 秒之间按 0.5 秒调整。成功提示音和成功震动各自独立开关，
偏好会保存在本机，下次打开仍生效。

只有包装真正加入草稿后才开始冷却并触发成功反馈。“已收录”提示至少保留
800 毫秒；重复包装不会触发声震、增加数量或重启冷却。同一二维码持续停留在
镜头中也不会在间隔结束后再次加入。不同包装但相同 SKU 仍可分别采集。
硬件缺失、静音或系统限制可能让声震不可用，屏幕提示仍然显示。

## 采集和核对

- Android 相机连续采集；Windows 扫码枪回车输入、逐行粘贴二维码载荷。
- 在当前草稿内按完整包装二维码去重：trim 后相同载荷只收一次，同 SKU 的不同包装分别保留。
- 采集不联网；结束后统一解析和查询，确认数量与库位后批量入库。
- 失败条目进入独立待处理页面，可重试、补料号和资料、修改数量、移除。
- 本地私有草稿支持恢复；二维码原文不进入诊断日志或同步服务。

## 数据与交互约定

单个草稿最多 500 个包装；每条拥有稳定 UUID。料号只能来自合法 C 编号，
不能从 URL 商品数字 ID 或订单号推断。包装数量必须是正整数；缺失、非法数量
需要人工确认，不能静默填 1 后入库。同 SKU 的查询在本次解析中复用，查询低并发，
支持取消，避免相机被商城请求阻塞。

核对页保留包装条目，并按 SKU / 库位展示入库增量汇总。统一默认库位可减少重复填写，
每条仍可调整。已有活跃 SKU 追加库存并保留原资料，新 SKU 要求必填资料完整。
可只提交准备好的条目，其余条目继续留在草稿或待处理页。

单条新增导入遇到已有料号时，也以“当前库存 + 本次入库 = 入库后库存”弹窗核对，
例如 15 + 15 = 30。确认后只追加选定库位的库存并生成入库记录，不覆盖原元件资料。
确认期间库存版本变化时，需要重新核对。普通编辑已有元件仍表示修改总库存，
不能把编辑操作解释为追加。解析、查询、保存错误使用明确弹窗；批量解析结束时
汇总失败数量并提供待处理页入口，避免逐条失败弹窗打断批量操作。

一次确认使用一个 SQLite 事务写入元器件合计、库位分配、入库流水、同步队列和
本地逐条提交凭据。数量相加检查溢出、目标库位有效、活跃 SKU 唯一；任一错误时
本次新增库存全部回滚。重复提交凭据不再次入库。应用在数据库提交后、草稿更新前
被关闭时，重启通过凭据识别已经完成的条目。凭据只用于本机同一条草稿记录；
新建草稿后重新扫描会被视为新的入库，不承诺跨批次或跨设备包装去重。

草稿与凭据不是库存同步载荷，也不作为 Excel 库存备份的组成部分。清空草稿前应
提示用户确认；清空未提交草稿不会撤销已提交库存。

## 中断与旧版回退

重新打开应用时先恢复草稿，检查条目是否已提交，再继续剩余条目。同一草稿的提交凭据用于识别已完成条目，避免重复入库。

旧客户端不应处理新草稿。已入库的结果属于正常库存和流水，回退应用版本不会自动撤销入库，应通过正常库存调整流程处理。相机扫码和扫码枪效果取决于设备，遇到问题可按[扫码诊断与反馈](feedback-and-scan-diagnostics.md)提供诊断。
