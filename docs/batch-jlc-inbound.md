# 嘉立创连续采集与批量入库

在 Android 打开「库存 → 导入与扫码 → 批量入库」，按手头资料选一种方式。三种方式共用草稿和复核页，确认后才入库。

| 手头资料 | 方式 |
| --- | --- |
| 多个有二维码的立创包装 | 连续扫码 |
| 自己整理的 C 料号和数量 | [批量 C 编码 / XLSX 导入](#c-编码清单) |
| 立创商城导出的物料明细对账单或订单详情 | [导入立创商城订单](#立创商城订单) |

## C 编码清单

选择目标库位，再粘贴文本或点击「从 XLSX 导入」。文本每行写一个 C 料号和正整数数量，用空格、制表符或逗号分隔，例如：

```text
C25804 100
C14663 50
```

XLSX 读取第一个可见工作表。前三列依次为「C 编码、数量、库位编码」，第三列可留空，使用界面选定的库位。支持有表头或无表头、空行，例如表头 `SKU / Quantity / Location`。库位编码使用应用保存的稳定 ID，需要新库位时先在选择器里创建。含公式的单元格请先粘贴为值。文件最多 10 MiB，每次最多 500 行，整个草稿最多 500 项。

**加入并解析**后，已有元件沿用本地资料，新元件可用目录查询补齐。同一份输入中，相同料号和库位的数量会相加。格式无效、库位不存在或数量溢出时，按提示的行号修正后再导入。

重导时应用列出和当前草稿重叠的料号、库位和数量。可取消、替换未入库的重叠草稿，或将本次数量额外追加。替换保留原有资料、勾选状态和采购总额，数量变化后请复核金额。若有多条重叠行且总数变化，请逐行修改。已入库行不能替换，需要更正时用库存调整。

## 立创商城订单

1. 选择已有库位，或创建新库位。
2. 选择立创商城导出的物料明细对账单或订单详情（`.xls`）。应用读取订购数量和商品行含税金额，忽略配送费和汇总行。订单详情有「订购数量（修改后）」时采用该列。嘉立创 EDA 设计 BOM 应从[项目用料](bom-and-migration.md#项目-bom)导入。
3. 在复核页确认数量、采购金额、库位和商品资料。缺项可在待处理页补齐，退款、取消或不发货的行先核对再决定是否入库。文件最多 10 MiB、500 条商品。[金额读取和补录规则](inventory-cost.md#立创订单导入)
4. 确认选中明细，已有 SKU 的数量增加到目标库位。已入库的同订单、同源料号会跳过，改文件名或重新选择日期区间不改变订单身份。跨设备的边界见[数据与交互约定](#数据与交互约定)。

## 扫码间隔与成功反馈

Android 在批量采集页的“扫码设置”中提供连续采集间隔，默认 1.5 秒，
可在 0.5–5 秒之间按 0.5 秒调整。成功提示音和成功震动各自独立开关，
偏好会保存在本机，下次打开仍生效。

只有包装真正加入草稿后才开始冷却并触发成功反馈。“已收录”提示至少保留
800 毫秒；重复包装不会触发声震、增加数量或重启冷却。同一二维码持续停留在
镜头中也不会在间隔结束后再次加入。不同包装但相同 SKU 仍可分别采集。
硬件缺失、静音或系统限制可能让声震不可用，屏幕提示仍然显示。

## 采集和核对

- Android 使用相机连续采集。历史 Windows 客户端可通过扫码枪回车输入或逐行粘贴二维码载荷。
- 在当前草稿内按完整包装二维码去重：trim 后相同载荷只收一次，同 SKU 的不同包装分别保留。
- 采集不联网；结束后统一解析和查询，确认数量与库位后批量入库。
- 失败条目进入独立待处理页面，可重试、补料号和资料、修改数量、移除。
- 本地私有草稿支持恢复；二维码原文不进入诊断日志或同步服务。

## 数据与交互约定

单个草稿最多 500 个包装；每条拥有稳定 UUID。料号只能来自合法 C 编号，
不能从 URL 商品数字 ID 或订单号推断。包装数量必须是正整数；缺失、非法数量
需要人工确认，不能静默填 1 后入库。同 SKU 的查询在本次解析中复用，查询低并发，
支持取消，避免相机被商城请求阻塞。

核对页保留包装条目，并按 SKU / 库位展示入库增量汇总。统一默认库位可减少重复填写，
每条仍可调整。已有活跃 SKU 追加库存并保留原资料，新 SKU 要求必填资料完整。
可只提交准备好的条目，其余条目继续留在草稿或待处理页。

单条新增导入遇到已有料号时，也以“当前库存 + 本次入库 = 入库后库存”弹窗核对，
例如 15 + 15 = 30。确认后只追加选定库位的库存并生成入库记录，不覆盖原元件资料。
确认期间库存版本变化时，需要重新核对。普通编辑已有元件仍表示修改总库存，
不能把编辑操作解释为追加。解析、查询、保存错误使用明确弹窗；批量解析结束时
汇总失败数量并提供待处理页入口，避免逐条失败弹窗打断批量操作。

一次确认使用一个 SQLite 事务写入元器件合计、库位分配、入库流水、同步队列和
本地逐条提交凭据。数量相加检查溢出、目标库位有效、活跃 SKU 唯一；任一错误时
本次新增库存全部回滚。重复提交凭据不再次入库。应用在数据库提交后、草稿更新前
被关闭时，重启通过凭据识别已经完成的条目。立创商城订单按订单号和 C 料号在本机跨草稿去重，重复导入会跳过已提交明细。包装扫码和 C 编码清单的凭据以草稿为单位，新草稿可以继续补货。
同一批货请选一种方式录入，应用无法判断扫描的包装是否已计入订单。

草稿与本地凭据不参与同步或 Excel 库存备份。新入库的已识别订单可随流水同步稳定来源键；另一台设备拉取到该键后会跳过同一订单商品。两台设备离线重复入库时，服务端会拒绝后到的整个冲突推送，不会自动合并库存。Android 可在同步冲突复核中处理可安全归档的重复项；无法证明安全时保留本地记录，Windows 同样保留未上传记录。

Excel 备份不保存来源键。恢复到新数据库后，历史订单身份未知，重导前应核对历史或先同步可用的来源记录。清空草稿前应
提示用户确认；清空未提交草稿不会撤销已提交库存。

## 中断与旧版回退

重新打开应用时先恢复草稿，检查条目是否已提交，再继续剩余条目。同一草稿的提交凭据用于识别已完成条目，避免重复入库。

旧客户端不应处理新草稿。已入库的结果属于正常库存和流水，回退应用版本不会自动撤销入库，应通过正常库存调整流程处理。相机扫码和扫码枪效果取决于设备，遇到问题可按[扫码诊断与反馈](feedback-and-scan-diagnostics.md)提供诊断。
