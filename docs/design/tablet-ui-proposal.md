# Android 平板布局提案

日期：2026-10-28。范围：原生 Android 客户端的布局与交互组织。

[打开交互原型](tablet-layout-proposal.html)。该 HTML 使用合成数据展示布局及部分点击交互，**尚未实现到 Android**，不连接真实库存或打印设备。原型里的密度选项、工作区组合和操作反馈不代表客户端已有功能。

dev23 的范围是键盘遮挡、操作栏可达性、内容裁切等显示修复。下述平板重排应在后续 dev 版本分阶段实现、实机验收；不能把原型预览或构建通过计作 Android 实现完成。

## 现有双栏为何仍像大号手机

当前已具备适配基础，问题不是简单缺少横屏分支：

| 当前源码 | 已有行为 | 仍需改善的地方 |
| --- | --- | --- |
| `InventoryAdaptive.kt` | 依据窗口宽度分类；非 Compact 支持列表详情，Expanded 使用表单 Dialog | 一个宽度分类同时决定多类页面行为，尚未表达每类内容的最小可用宽度 |
| `InventoryScreen.kt` | 使用 `NavigableListDetailPaneScaffold`，关联选择与详情 | 列表筛选、逐项信息和详情仍沿用纵向内容；增加窗格并不自动提高横向信息利用率 |
| `SettingsScreen.kt` | 分组/摘要与设置详情按 `0.9f/1.1f` 分栏，分别滚动 | 分组栏占用接近一半宽度，真正要输入的表单仍需纵向查找 |
| `BomImportScreen.kt` | 匹配预览是纵向 `LazyColumn`，包括摘要、问题、逐行操作 | 核对需求、匹配结果、可用量时需要上下阅读，缺少对齐的比较区域 |
| `BluetoothLabelPrintScreen.kt`、`LabelToolTemplatePicker.kt` | 已有画布、模板选择、属性/内容面板和打印流程 | 画布与设置依赖切换或面板，宽屏没有持续并排展示模板、画布、属性 |
| `StorageLocationsScreen.kt`、`KittingScreen.kt` | 库位卡片列表；配套件搜索、已选项和复核纵向组织 | 查找对象与核对结果的关系不够直接，需要反复滚动 |

因此优先改变信息层级、列宽与工作区职责，保留 Material 3 控件和现有业务流程。不要只把手机卡片拉宽，也不要为了塞更多内容缩小字体或触摸目标。

## 布局判断：按可用空间与内容预算

采用窗口尺寸及扣除导航、系统栏、页边距后的内容宽度；分屏、自由窗口与旋转均触发布局计算。键盘出现还需重新约束可见高度。**横屏不必强制多栏，竖屏也不必强制单栏。**

以下尺寸为首轮设计起点，单位 dp，需以中文长文案、系统字体放大及实机确认后调整，不作为平台标准：

| 工作区 | 起始空间预算 | 空间不足时 |
| --- | --- | --- |
| 库存 | 列表 320–400；详情至少 400；栏间 16 | 列表/详情逐页显示，保留选中项及返回位置 |
| BOM | 表格至少 560；匹配辅助至少 320；栏间 16 | 辅助区改为所选行的独立详情或可关闭面板；表格保留核心列 |
| 标签 | 模板/元素 200–240；画布至少 420；属性 280–320；栏间各 16 | 先收起模板区，再将属性改为可展开面板，始终优先保证画布 |
| 库位/配套件 | 对象导航 240–280；内容至少 400 | 顺序进入对象和内容，不压缩成两个难用的窄栏 |
| 设置 | 分组 220–280；表单至少 360，正文上限约 640 | 分组列表进入单页表单；宽屏剩余空间留白 |

优先复用项目已引入的 Material 3 Adaptive 能力，按窗格职责调整约束；仅在需要知道实际内容宽度时局部使用约束测量。不要扩展成新的全局布局框架。常规间距沿用 8/16/24dp，输入框及操作保持原生可访问性，焦点清晰可见。

## 页面方案

### 库存：列表与详情

左侧集中搜索、筛选和紧凑列表。每行稳定展示名称/SKU、封装、库位、数量与低库存状态；长文本省略后在详情查看，关键数量不靠颜色单独表达。搜索和筛选不要挤成一条不可读的工具栏，宽度不足时换行。

右侧先展示名称与库存摘要，再按基本信息、各库位库存、说明/照片组织；编辑、记录流水、标签操作靠近当前元件。复用现有详情与回调，不在布局重排中新增库存动作。未选中时显示明确提示；空库存、无搜索结果、加载失败分别给出已有可执行入口。切换列表项仅更新详情，不改变筛选。

### BOM：表格与匹配辅助

主区按行对齐需求型号/封装、需求量、已匹配元件、可用量、状态；数量列右对齐，长描述放入行详情。问题筛选与总体复核状态置于表格上方。行选择后在辅助区展示当前需求、候选元件与库位分配，复用现有匹配、跳过和复核逻辑。

确认按钮位于稳定操作区，滚动由表格自身承担。仍遵循现有提交条件与确认流程；切换候选和窗格不自动提交。较窄窗口显示核心列及所选行详情，不能让整页无限横向滚动。空文件、解析失败、无匹配和库存不足继续使用实际业务状态，原型占位数据不进入实现。

### 标签工具：模板/元素、画布、属性

宽屏让模板与元素导航、按纸张比例缩放的画布、所选元素属性并列。纸张尺寸持续可见；属性分为元素与纸张，选择元素后显示对应设置。复用现有坐标、模板、内容与渲染模型，不能因屏幕重排改变毫米尺寸、二维码内容或打印产物。

中等窗口保留画布与属性，模板以明确入口展开；窄窗口保留现有分步操作。键盘打开时优先保证当前属性字段、返回/关闭和确认入口可达；关闭面板后恢复画布选中元素。打印队列与实际发送状态沿用现有流程，布局预览不等于打印验证。

### 库位与配套件：导航与工作内容

库位管理左侧按现有库位列表选择对象，右侧显示库位信息及相关元件入口；新增、编辑、删除、库位标签继续使用原有权限和确认行为。原型中的“库位与配套件”组合是入口组织建议，不代表两种数据模型已合并。

配套件宽屏把库存搜索/候选与已选物料及复核摘要并排，添加或替换后保留搜索位置和当前草稿。复核仍先于库存扣减，确认一次的语义不变。无库存、未选料、缺料及操作进行中均有明确状态；中断恢复沿用既有会话能力，不承诺新增持久化。

### 设置：紧凑分组与限宽表单

左侧采用紧凑分组导航，摘要收为少量状态行；右侧表单限宽，按同一任务分组。服务器地址、账户绑定、同步状态保持现有含义；标签、数据管理等入口只重排已有设置。较短选项可按行排列，长说明放在所属字段附近。

各分组保留当前未保存输入及滚动状态，缩窄时回到单页导航；切换布局不能触发保存或重新绑定。明确区分保存中、成功及失败，失败允许继续修改并重试。原型中演示的开关与选项必须逐项对照现有功能后再决定实现，不把占位选项直接加入产品。

## 实施与验收

| 阶段 | 变更范围 | 完成标准 |
| --- | --- | --- |
| dev23：显示修复 | IME、有限高度滚动、顶部/底部操作可达 | 已覆盖的问题在设备上复测，记录横竖屏与键盘场景；本阶段不宣称完成平板重排 |
| 后续 dev 第一阶段 | 库存与设置的空间预算、列表密度和表单限宽 | 宽窗口可同时阅读关联内容；不足宽度可靠退回单页；筛选、选中项、草稿及返回位置不丢失 |
| 后续 dev 第二阶段 | BOM 表格及匹配辅助 | 使用独立样例核对问题筛选、选行、匹配和复核；切窗格不提交、不改变数量和分配 |
| 后续 dev 第三阶段 | 标签工作区、库位及配套件 | 模板/元素/属性关联正确；纸张尺寸和渲染结果不变；配套件仍经原有复核再扣减 |

每阶段只验证受影响页面及直接关联行为：在实际平板横竖屏、一个明显不足双栏宽度的窗口、键盘展开和系统字体放大场景检查。覆盖长 SKU/名称/库位、空态、错误态及已有草稿；触摸和键盘焦点都能到达操作，返回保持上下文。布局测试负责约束与导航回归，实机检查负责输入法及窗口表现；打印相关另以实际设备结果记录，不能用截图替代。

保留现有 ViewModel、离线 SQLite、会话/草稿与数据来源，仅改变呈现和页面导航状态。不得因尺寸变化重建业务会话、清空数据、自动同步或重复提交；本提案不改变协议、schema、账户绑定或同步边界。分阶段发布 dev 后再验收，稳定版本由用户决定。

## 参考与取舍

- [Android 官方 Canonical layouts](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts)：采用列表详情、主内容与辅助区等职责划分，并在窗口变化时保持选择状态。本提案的具体尺寸是项目建议。
- [官方 compose-samples / Reply](https://github.com/android/compose-samples/tree/main/Reply)：参考可用窗口变化时调整导航与列表详情的方式；不照搬邮件界面的信息结构。
- [官方 Now in Android](https://github.com/android/nowinandroid)：参考 Compose 应用组织与原生自适应实现方式；库存与 BOM 仍按当前任务设计，不复制资讯流布局。

以上参考用于后续实现选择，不表示已在本项目安装、运行或完成这些样例的实机验证。
