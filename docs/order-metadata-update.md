# 用立创订单更新已有元件资料

Web 库存页提供“从订单更新资料”。本工具只修改当前账户已有元件的中文分类、封装和订单内明确的电气参数，不增加库存，也不导入新元件。

## 操作步骤

1. 先让 Android、Windows 设备把待同步修改同步到同一服务端。服务端与 Web 管理台都需升级到含本功能的版本。
2. 在 Web“库存”打开“从订单更新资料”，选择立创商城导出的旧版 BIFF `.xls` 订单/物料明细表。首版不支持 `.xlsx`、CSV、改扩展名的 HTML 文件。
3. 点击“生成只读预览”。系统按精确 C 料号匹配当前账户未删除元件，列出旧值、新值和来源行；订单号及购买数量不用于修改库存。
4. 勾选要更新的字段。分类、封装、参数组可分别取消；将某元件全部字段取消即可不更新它。默认保留现有名称，即使订单型号或商品名称不同也不会改名。
5. 点击“确认更新”，核对数量后确认。这里的项数是元件条数，不是出入库件数。Web 库存操作关闭时可以预览，但不能应用；管理员可从现有服务端配置启用。
6. 查看逐条结果。成功项保留；请求结果不明或失败可使用原请求 ID 重试；版本冲突需要重新预览，不能强制覆盖。完成后再让 Android、Windows 同步，即可拉取新分类、封装和参数。

## 保留与限制

- 保留已有名称、SKU、数量、最低库存、主库位、库位分配和历史流水。没有数据库 schema 迁移。
- 保留原图、图片关联行和用户自由备注。参数只替换被选择键的 `参数·键：值` 行，包括英文同义键；其它参数和备注逐行保留。
- 只采纳中文分类来源，空白来源不会清空已有分类/封装。同 SKU 多行资料不一致时标为冲突，不自动取最后一行。
- 参数取自明确列或带单位的商品描述；没有明确阻值、容量、电感量等时，不从型号编码猜测。没有中文分类的英文行不会冒充中文分类。
- 最大 16 MiB、500 个唯一 SKU；超过时请拆分。原始订单不长期保存。关闭面板或离开页面会丢失本次预览，已成功更新的服务端数据保留。
- 更新期间如果设备发生出入库或编辑，服务端版本检查会提示冲突。建议完成待同步更改后再批量更新。旧标量快照仍遵循既有整行 LWW，工具没有新增字段级冲突合并。

## 部署（0.7.8 正式版起）

本功能需要新 API 和 Web 一起部署；仅更新手机 APK 或 Web ZIP 不会给旧 API 增加接口。0.7.8 正式发布提供 API `0.7.8` / `latest` 和 Web `web-0.7.8` / `web-latest`；先确认对应镜像已发布，再按 [Docker 部署教程](dockerhub.md)拉取并重建原项目，保留原 `/data`。早期 dev.21 发布时没有替换这些稳定标签。

源码部署可在已备份并保留原 `/data` 映射、Compose 项目名称的部署目录中，获取 `v0.7.8` 源码，重建 `api` 与 `admin-web`：

```shell
docker compose build --build-arg APP_VERSION=0.7.8 api admin-web
docker compose up -d api admin-web
```

以上对应仓库的 `docker-compose.yml` 源码构建方式。现有 Docker Hub 部署需保留原数据库/配置/日志/照片映射后再切换到源码构建，不能直接更换项目名生成一个新空数据卷。不要执行 `down -v`；先按[备份与恢复](storage-and-backup.md)保存数据。未迁移 schema，可保留原数据卷回退到原版 API/Web。

## 版本与验证范围

此功能从 0.7.8-dev.21 引入，包含在 0.7.8 正式版。已有隔离账户的 Web、Windows 同步和 Android 实机验证记录，涵盖资料更新及库存、流水、照片保留；不代表所有订单格式均已验证。详细证据见[历史验证记录](history/verification.md)。
