# 元件照片跨设备同步

## 使用方法

1. 先升级 API 和 Web，再升级需要互通的 Android / Windows 客户端。照片同步需要 0.7.8 或更新版本。部署可参考[源码 Compose 构建步骤](runbook.md#docker-deployment)。
2. 两台设备配置同一服务端、同一账户。原生客户端仍先保存到本机；不配置服务端也能拍照、选图和离线使用。
3. 在元件编辑器拍照或选择 PNG / JPEG，保存元件，再执行“立即同步”。照片在库存元数据成功后单独传输；一次成功保存不需要等待网络。
4. 另一台设备执行同步后即可显示照片。Web 库存列表和详情通过登录会话读取已上传原图，不需要暴露 API Token。
5. 下载完成的照片在设备离线时仍可查看。照片文件单张不超过 5 MiB，沿用现有客户端 4096×4096 尺寸约束；供应商公开商品图片仍按原来的地址与缓存规则处理。

## 状态与重试

设置页显示照片在本机的可用情况、已上传/下载数、待处理或失败数、最近照片完成时间，以及具体问题。没有可靠总量时不显示百分比。

- **尚未配置**：照片已保存在本机，配置同步服务后可上传。
- **待同步 / 待下载**：关联已经存在，文件还没有在两端就绪；点击“立即同步”继续。
- **传输中断**：已经完整落盘的文件保留，下次同步重新计算剩余项，不要求重新拍照。
- **部分完成**：已完成的库存和预设保留，照片失败不会撤销库存操作。修复网络或原图问题后再次同步；即使没有新的库存变动，也会重新检查照片。
- **缺少原图**：本机和服务端都没有该引用的文件。请让仍保存原图的设备同步，或在编辑器重新选择照片。应用不会擅自清除照片关联。
- **服务器暂不支持**：本地照片与库存同步继续可用；升级 API 后重试。

库存的成功时间与照片的成功时间分别说明范围。照片失败时不能把库存成功解释为所有照片已经上传。Web 可以确认服务端已收到文件，无法确认某台离线设备是否已下载。

## 替换、删除与冲突

照片关联使用元件说明中的图片标记；替换或移除照片随元件保存同步。其他设备尚未下载文件不代表照片已被删除。并发编辑沿用元件版本检查 / LWW 行为，不提供照片人工合并界面。

文件按现有内容摘要命名，重复同步不会生成另一份相同原图。服务器只接受当前账户元件引用的文件；不同账户通过各自数据目录隔离。服务端不会改变库存数量或生成出入库流水。

## 缓存与备份

- Android 原图仍在原 `files/images/`；下载副本在 `files/photo-downloads/`。
- Windows 原图仍在库存目录的 `images/`；下载副本在 `images/downloaded/`。
- 设置中的“清理照片下载缓存”只删除下载副本，保留用户原图和照片关联。清理后重新同步即可下载；没有原图的下载副本在未同步时请先备份。
- 客户端自动清除不再被有效元件引用的下载缓存和中断临时文件；不会据此删除用户拍摄、选择的原文件。
- 服务端文件位于 `<账户数据库完整路径>.photos/`，与 SQLite 同在数据卷中。超过 24 小时且未被当前有效元件引用的服务器文件和上传临时文件，会在照片清单请求时清理；删除普通账户也会删除其照片目录。
- 完整服务端备份应同时保存账户数据库、配置和 `.photos` 目录，推荐备份整个 `/data`。仅复制 SQLite 不包含照片字节。
- Excel 库存备份会读取本机可用的原图和下载照片；尚未下载的照片无法凭标记进入备份，先同步完成再导出。BOM 预设仍需按既有说明单独备份。

## 部署升级

不增加环境变量、外部对象存储或额外端口。原 `/data` 数据卷同时承载照片；保留现有挂载，确认可写且有足够空间。API 与 Web 一起更新；客户端从 `/auth/ping` 的 `photo_protocol: 1` 判断支持。照片同步接口独立于库存游标，网络失败后可以重试，不清空既有数据库。


## 同步中断、取消与重试

运行时设置中的“立即同步”会变为“取消同步”。取消保留本机资料与已经完成的库存和文件；重新同步会依据队列、预设确认版本和照片 manifest 继续收敛，不需要清库。应用被结束后重新打开，遗留的运行状态显示为中断；不会把库存成功当成预设和照片全部完成。

库存、BOM 预设和照片的最近完成时间各有范围，不能用库存时间判断所有内容已经同步。若传输期间又在本机修改资料，该修改显示为待下次同步处理；离线设备仍可查询和编辑本机数据。更换连接配置或账户不会复用旧范围的成功状态。未开始或失败的任务通过同一“立即同步”入口重试，不新增自动后台任务。
