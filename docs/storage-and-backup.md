# 库位、库存转移与 Excel 备份迁移

## 标签打印专用 Excel

Android 和 Windows 的“Excel 备份与恢复”页面增加独立的标签数据导出。
默认导出当前本地库存中全部未删除元件，一元件一行，不包含已删除记录。
可选择名称、SKU、型号、封装、分类、库位、当前数量、长二维码文本、短二维码文本；
默认勾选名称、SKU 和两种二维码文本。空库存时禁用导出。

导出范围可选“全部库位”或“指定库位”。默认全部库位，沿用一元件一行及总库存数量；
指定库位支持多选，可只选一个库位分批导出。此时按“元件＋库位”分行，
同一 SKU 位于两个已选库位时会导出两行，数量及二维码中的数量分别使用该库位库存，
不会把其他库位的数量一起带入。未分配库位的旧数据可通过“未指定库位”选择。
导出前显示预计行数；未选择库位、没有匹配元件或未选择字段时不能继续。
建议同时勾选“库位”和“当前数量”，便于第三方标签软件区分各行。

文件是真实 `.xlsx`，仅包含选中的列。SKU 和二维码以文本单元格保存，
避免前导零丢失、被当成数字或公式。长码沿用完整仓库码或 JLC 兼容码，
短码沿用 `cvl3` 查找码；第三方打印工具应把对应文本列映射为 QR 内容。
短码需要库存中存在相应 SKU 才能取得完整资料。

标签文件不是库存备份，不能替代“导出完整备份”，也不作为备份恢复输入。
导出只读取库存，不扣减库存。保存对话框取消时不会写入文件。

Android 与 Windows 使用相同的元器件与库位模型，所有库存操作先写本地 SQLite。
汉印 M1 的 Android 蓝牙打印已有独立操作流程，见 [M1 标签打印](m1-printing-feature-matrix.md)。Excel 标签导出不需要连接打印机。

## 库位和转移

一个 SKU 对应一条元器件资料；同一物料可以分配到多个库位。库位编码是稳定标识，
创建后不能改码，显示名称可以编辑。没有物料的空库位也可以提前创建。

新增时会检查库位编码是否已存在，前后空格不会形成另一个新编码。重复编码会报错，
不会覆盖原名称、库存分配或数量；已删除库位的编码也保留，不会通过新增偷偷恢复。
需要修改名称时，请使用原库位的“编辑”。编码是唯一标识，显示名称不是唯一标识。
如果旧版本已将库位改名，先按原编码检查分库位数量，再编辑回正确名称；
升级不会自动猜测并还原被覆盖的名称。

元器件详情列出分库位数量，库存列表显示合计。出入库选择实际库位；调拨选择来源、
目标和数量，可以移动一部分或全部。来源不足、相同源目标、非法数量都会拒绝整个操作。
调拨产生一条带来源和目标的记录，总量不变，已出库统计不会增加。

Android 出入库数量框提供“− / ＋”按钮，每次调整 1 个；可以直接把默认的 1 加到 2，
无需打开键盘。大数量仍可点击数字手动输入，修改数量后仍需确认才会写入库存。

BOM 预览列出各元器件的具体扣料库位，按客户端展示的确定性分配顺序生成。
确认时再次核对版本、各库位余额与分配计划，有变化时需要重新预览，不执行部分扣料。

## 扫嘉立创包装出库

Android 进入“记录 → 扫描标签”，可直接扫描嘉立创原厂包装二维码，也可扫描应用生成的仓库标签。
识别后按料号精确匹配本地未删除元件，成功后关闭相机并进入复核页面。
选择“出库”，确认元件和数量后再提交；首次扫描默认数量 1，不使用包装上的整包数量自动扣库。
需要增减可使用数量框的加减按钮，也可手动输入。继续扫描必须显式点击追加扫描入口。
本地没有该料号时需先入库；扫码不会联网新建元件，也不会因为型号相近而扣减另一种物料。

## 库存检索、批量转移与删除

库存搜索支持型号片段、品牌和官方参数；空格分词可以跨名称、SKU、分类、封装、库位和说明匹配。
例如 `FOJAN 10k`、`富捷 0603`、`100uF 1206`。μ/µ/u、Ω/ohm、全半角及常见型号分隔符
会归一，不自动猜测不同数字或规格之间的替代关系。旧记录没有保存品牌或参数时，搜索不会凭空补全。

Android 在库存页进入多选，Windows 勾选库存行后选择“批量转移”。选择共同有库存的来源库位
和不同的目标库位，各项默认转移来源的全部可用量，也可逐项减少。复核后一次提交：会重新检查
库位、元件版本和余量，任一项失效则整批不写入。成功后每个元件生成转移流水，各元件总库存不变，
待同步队列沿用现有库存同步机制。要移动来源不同的元件，请按来源分别操作。

Android 库存卡片左滑展开“入库、出库、转移、删除”四个快捷操作。
入出库在当前弹窗调整数量和库位，转移选择来源与目标；不必先打开元件详情。
多选时关闭左滑操作。删除仍需确认并沿用软删除，一次滑动不会直接删除，也不等同于出库。
Windows 使用库存行或详情中的鼠标操作。

## 同步升级

先升级服务端，再升级客户端。新客户端在同步前检查 `inventory_protocol=1`；
旧服务端不能接收新库存格式，客户端会停止同步并保留本地队列。
已有库位字符串会迁移成单库位分配，原 SKU 与数量保留，升级前保存本地数据库备份。

元器件总量与完整库位分配作为一个快照提交。`base_updated_at` 是客户端上次确认
的服务端版本；另一台设备已经修改同一物料时，服务端返回 409，整批上传回滚。
这不是多设备离线操作自动合并，也不是跨设备 BOM 幂等。发生冲突后保留各端备份，
核对服务器库存和本地记录后再处理，不能把冲突提示当作已同步成功。
已升级为多库位的元器件，旧客户端不能再覆盖它。

## Excel 备份与恢复

自有 `.xlsx` 文件包含五张表：

| 工作表 | 内容 |
| --- | --- |
| meta | 格式 `component-vault`、schemaVersion=2、导出时间 |
| components | 元器件资料、合计数量、阈值、版本及商品图片 |
| storage_locations | 独立库位编码、名称及删除状态 |
| allocations | 元器件和库位的数量分配 |
| stock_movements | 出入库、调整和转移历史 |

两端使用同一格式。导出读取一致的本地库存，不联网补全、不改库存、不导出同步令牌。
图片只导出已在本地可用的资源；未下载的网络图片不因导出而触发网络请求。

导入先显示来源、数量、冲突和警告。确认后整批事务写入；文件本身保持不变。
当前恢复方式是**导入新记录**：已有元器件 ID 或 SKU 冲突需要先处理，不自动覆盖、
相加或清空当前库存。恢复到空库存可以保留备份中的元器件与流水；同文件重试有本地
指纹记录，防止重复导入。服务器配置、导入学习和 BOM 批次偏好不属于此 Excel 格式。

只接受规范 `.xlsx`，旧 `.xls` 应先另存。数量必须为整数；公式不能作为库存依据。
导入检查重复标识、孤立引用、负数、溢出、分配合计和历史转移字段。
库存备份采用独立容量限制：文件最多 50 MiB，解压后总量最多 100 MiB，单个 XML
最多 20 MiB，ZIP 条目最多 10000。图片单张最多 5 MiB、尺寸最多 4096×4096、
总量最多 25 MiB。每表最多 100000 条数据行（另加表头）；BOM 的 5000 行限制不再用于完整库存备份。
导出前会按读取规则验证产物，超限时明确报错，不将不可恢复的文件报告为备份成功。
原始 SQLite 升级前备份与 Excel 数据交换用途不同；回退旧二进制需要恢复升级前数据库，
不能直接让旧版本写入新库存结构。

### 文件格式与字段

工作表顺序为 meta、components、storage_locations、allocations、stock_movements。
meta 无表头，以 key/value 两列记录 format=component-vault、schemaVersion=2、exportedAt=UTC ISO。
新版兼容读取旧 schemaVersion=1；旧备份没有成本字段，恢复后为成本未知，不当作零成本。

- components: id,sku,name,category,package_name,location,description,quantity,min_stock,updated_at,deleted,base_updated_at,image_preview,inventory_unit_cost
- storage_locations: id,name,updated_at,deleted
- allocations: component_id,location_id,quantity
- stock_movements: id,component_id,movement_type,quantity,reason,note,happened_at,updated_at,deleted,location_id,destination_location_id,purchase_amount,cost_amount

ID/SKU/库位编码为字符串，数量为严格整数，deleted 为 Excel Boolean，null 留空。
成本字段也是文本单元格，保留十进制精度；明确零金额保存为文本 `0`，未知金额留空。
`inventory_unit_cost` 为当前人民币库存均价，流水金额说明见[成本指南](inventory-cost.md)。
内嵌图片位于 components 对应行 image_preview 列，one-cell anchor，PNG/JPEG，每组件最多一张。
LCSC_android_erp 迁移使用其原始 camelCase 表头、epoch millis 时间，不与本项目格式混淆。


## LCSC_android_erp 数据迁移

从该应用导出 schemaVersion=1 Excel 备份后，在本项目的备份导入入口选择文件。
识别其 `meta`、`storage_locations`、`components`、`inventory_items` 工作表。
库位 ID 映射为稳定编码，合并同一元器件的不同库位分配，保留品牌、参数、描述与来源信息。
源文件的嵌入商品图按图片资源导入，不执行工作簿中的公式或外部链接。

该来源格式没有导出库存历史流水，因此只生成注明迁移来源的初始入库记录。
不能从现存数量反推曾经出库多少；源文件本身未包含的型号或历史也无法恢复。
`component-hub` 的 JSON 迁移在 Windows 保留入口；Android 已移除日常菜单入口，详见 [BOM 与迁移](bom-and-migration.md)。

迁移格式参考 [LCSC_android_erp 固定提交](https://github.com/BrokenClient/LCSC_android_erp/tree/7a40b842b8dfa94fd2168c38a9ddcc3411997b83) 的 InventoryBackupManager。

## 导入学习映射

启用本地导入学习后，导入确认保存的名称（包括型号形式名称）、分类和封装会用于后续匹配。联网查询补齐缺失信息，保留已学习或手动指定的非空字段。映射保存在当前设备，不会因本次修复被清空；已经错误写入库存的资料不会自动批量改写。

## 立创订单对账单导入

Android 在“导入与扫码 → 批量嘉立创入库”中选择“导入立创商城订单对账单（.xls）”。目前识别商城的旧版 BIFF 物料明细对账单，不把嘉立创 EDA BOM 当订单入库。

1. 先选择已有库位（显示名称），或创建新库位。
2. 选择导出的 .xls 文件，自动读取商品编号、商品型号、商品名称、品牌、商品类型、封装格式和订购数量；配送费与汇总行忽略。
3. 在复核页检查数量、库位及商品资料，缺字段的明细在待处理页补齐。订单表没有完整电气参数列时，不从型号编码推测参数。
4. 确认选中明细入库，已有 SKU 累加数量。相同订单同料号已在本机提交后，再导入会跳过，变换文件名或日期区间不会重复入库。

最多 500 条订单商品、文件上限 10 MiB；取消或退款明细需要先核对。去重回执是本机数据，不在不同设备间共享，避免在多台设备分别导入同一订单。

## 手工元件与照片

没有商城料号时 SKU 可留空，保存会生成唯一 CV- 内部编号。照片可拍摄或从图库选择，按“使用照片”后随元件保存；取消编辑清理本次新建照片。图片先保存在本机，配置支持照片协议的服务端后可跨设备同步；本机可用的图片包含在 Excel 备份中，具体范围见下文。
## 照片同步后的备份

本机已下载的照片与原图都可进入既有 Excel 图片备份；尚未下载的引用不等于图片字节，先同步完成再导出。服务端应备份整个 `/data`，包括各账户数据库旁的 `.photos` 目录。下载缓存清理、失败重试与升级步骤见[照片同步教程](photo-sync.md)。
